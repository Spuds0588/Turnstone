## v0.14 Workspace links, and a site that agents can read
- [x] **Workspace links — a whole list inside a URL.** `app.html#zdata=<payload>&sum=<length>.<hash>` opens a ready-to-work queue with nothing fetched and nothing uploaded. `#data=` is the same list as percent-encoded text, for a handful of rows and for a person or model writing one by hand; `?data=` is read too, for a tool that can only append a query. `&format=` forces the reader, `&name=` labels the workspace, `&link=` composes each row's URL from its own values (`{Column}` percent-encoded, `{Column|raw}` verbatim, `{0}` by position), and `&open=1` opens the first task. The encoder picks whichever form is shorter, so a ten-row list stays readable text.
- [x] **The fragment, not the query string — and both reasons are load-bearing.** A fragment is never sent to a server, so a list of client names handed over this way stays out of the host's logs, which matters for an app whose whole claim is "nothing is uploaded". And a query string is part of the request line, which is size-limited: nginx's default 8 KB header buffer answers anything longer with a `414`, so a long `?data=` would be refused by the host before our code ran. Both were verified rather than assumed.
- [x] **The checksum, because a truncated link can be silently wrong.** A deflate stream cut at a *block boundary* inflates **without error**, producing a shorter list that looks completely normal — nothing else in this codebase fails that way, and a silently short queue is the worst thing the app could hand someone. Every link we build now carries `&sum=<base36 length>.<fnv1a32>`, verified when present and ignored when absent (a hand-written link cannot compute one). The suite compresses a 4,000-row list and cuts it at nineteen points: not one cut may load a *different* list quietly. The engine's own wording for a broken stream — `Failed to fetch` — is also translated into something a person can act on.
- [x] **The builder, in the app where it can preview.** **☰ → Build a share link…** (or `?build=1`) starts from the list you have open or from a paste, reports what it read (format, tasks, columns, header detected, whether a portal template will be needed), offers the columns as chips for the template, previews the URL, and warns past 100 KB. **☰ → Copy share link** is the one-click path, and it now works for a list with **no address of its own** — a local pick, a drop, a paste — by carrying the rows plus the ticks and notes entered so far, instead of the menu item being disabled.

## v0.13 Real queues, portal lists, email and paste — and an answer on OCR
- [x] **The workflow family → 9 fixtures** (emitted by `assets/make-fixtures.js`). Six lists from the recurring shapes of back-office work (service-desk queue, hand-kept triage sheet, accounts-payable workbook, vendor onboarding, renewals register, meeting action log) plus three no-file arrivals. (2) `Stage`/`Phase`/`Progress`/`Result`/`Outcome`/`Disposition` were not status columns, so a pipeline lost every tick made in the system it came from. (3) `Ticket, Summary, …` titled every card with the ticket number: `HEADER_NAME_RE` now knows the trackers' words and `HEADER_ID_RE` marks the find-a-row ones. A fourth: a link-free list could not be recognized as *having* a header row, because the heuristic needed a link below the first row.
- [x] **Portal lists — work that lives behind one URL.** For the four fixtures whose rows are keys into a system, not addresses: a **portal link template** (`?link=`, the settings field, or the prompt that appears on a link-free list), remembered per column layout and shareable as one URL. `{Column}` is percent-encoded from the row, `{Column|raw}` splices verbatim, `{0}` works by position, a template with no placeholders covers the literal *one portal, no per-row link* case, and a composed link behaves like a page everywhere (cards, open modes, `?open=1`). - [x] **Email (`.eml`, `.mht`, `.mhtml`).** Real MIME walking — nested multipart, folded headers, base64, quoted-printable, declared charsets — with the body's table preferred over the plain-text copy of itself, and **an attachment handed back to the ordinary detector**, so a forwarded `approvals.csv` opens as a CSV. A page saved from a portal that will not export is the same container, so one parser reads both. Prose bodies and non-rectangular plain-text bodies are refused rather than guessed at.
- [x] **Paste a list.** Ctrl+V anywhere in the app (not in a text field) offers the clipboard table — `text/html` when it holds a real table, else the tab-separated text — behind a confirmation with a preview, because a paste must never silently replace the queue you are working through. Also a menu item that reads the clipboard directly where the browser allows it. In the bookmarklet the listener is scoped to the overlay.
- [x] **An answer on OCR and a small local model — both are WebAssembly, and our own CSP refuses WebAssembly.** Demonstrated with the app's byte-identical policy: `CompileError: Refused to compile or instantiate WebAssembly module because 'unsafe-eval' is not an allowed source of script in the following Content Security Policy directive: "script-src 'self' 'unsafe-inline' file:"`. tesseract.js is ~7 MB (core + trained data), `needle-rs` is 600 KB of WASM plus a 13.7 MB model, and Needle is a *tool-caller* (`(query, tools) → call`), not a schema extractor — using it to normalize a messy list means describing the target JSON as a tool and trusting 45M parameters on freeform input. Either would cost the directive that makes this app's no-remote-code claim credible, for inputs that are rare here **and** that the paste path already handles exactly rather than approximately. Recommended: don't. If it is revisited, the shape is an opt-in separate edition with its own policy, and only after the deterministic normalization work above — which is what actually moved the needle on "badly formatted lists".
- [x] **Suites: 196 → 332 (Node), 22 → 52 (browser, per edition), 64 → 81 (bookmarklet).** New Node sections for workflows, portal composition and email MIME; the browser sweep gained the workflow/portal/email/paste sections; the bookmarklet matrix gained the new fixtures in all three variants (including `.eml` in the zero-library one).
- [x] **A real bug the harness found: fallback mode blocked every reload.** `saveNow()` left `state.isDirty` true after a successful snapshot "until exported", which armed the `beforeunload` guard permanently — every reload and tab close raised a *"you have unexported changes"* confirm over saved work. A prompt that always fires is one people learn to click through. `persistSessionSnapshot()` now reports whether the snapshot landed and dirty reflects that, so a build with no durable storage still keeps its guard armed.
- [x] **Two engine differences found and handled.** Node's `windows-1252` decoder returns U+0092 where a browser returns U+2019 (Outlook's curly quote) — so the Node suite asserts the byte survives and the browser sweep asserts the quote. And the standalone in a bare directory registers **zero** service workers (`sw.js` a 404 beside it), which closes the anomaly the previous session left open: the earlier "standalone registered a SW" reading came from serving the repo root, where `sw.js` happened to be a sibling.
- [x] **One generator for the whole fixture family — `assets/make-fixtures.js`.** The canonical queue is declared **once** (`HEADERS` + `ROWS`) and rendered into all eleven containers, with the workflow lists declared beside it, so the two former generators are retired. Second, the generator reports bytes per file and refuses to be a no-op silently: `node assets/make-fixtures.js --check` exits non-zero if any fixture in the tree differs from what the definition produces, and it is now part of the routine before a release. Regeneration was proven safe rather than assumed — against the pre-generator copies, **`sample-links.tsv`, `.html`, `.md` and `-table.md` came back byte-identical**, the JSON is structurally identical (pretty-printing), the XML differs only in its own comment, and the two binaries differ only where intended: the DOCX names this script in its trailing paragraph, and the XLSX is now **2,102 bytes instead of 17,881** because the hand-written ZIP writer replaced SheetJS's. ## v0.12 Markdown import (2026-09-25)

**Shipped.** One `FORMAT_INFO` row, one `EXT_FORMAT` alias set, one `parseMarkdownText()` and one sniff test — and it works in **every** edition, including the zero-library `csv` bookmarklet, because markdown is plain text. The design bet paid off exactly as written: a task list *is* already a four-column table, so `- [x] Finish the audit — https://acme.example — called Tuesday` becomes Name / URL / Status / Notes, and the emitted matrix is indistinguishable from the CSV fixture's — `urlCol=1, nameCol=0, statusCol=2, notesCol=3`, 10 cards, 7 visible, **3 complete**, 5 notes. Both shipped fixtures (`sample-links.md` as a task list, `sample-links-table.md` as a pipe table) hit the same target as every other format, verified in-browser through `loadMatrix` and in a 43-assertion Node suite over the real source slice.

Three decisions that were not in the plan, all forced by testing:
- **A `tel:`/`sms:` target needs a permissive number matcher.** The first scan captured `tel:+1` from `tel:+1 (555) 987-6543` and left the rest of the number in the note — a real bug the test caught. The scheme alternatives are now value-shaped (`mailto:` an address, `tel:`/`sms:` a run of digits with spaces/parens/dots/dashes, optional query consumed and dropped) instead of a generic "non-whitespace after the scheme", which is the rule that made spaces look like the end of the link.
- **`- Task (https://link)` leaves a bracket pair split across name and note** (one half before the link, one after). The two halves are now dropped together, and only when they actually pair — so a note that legitimately starts with `(` survives.
- **Sniffing is deliberately narrow.** Only a checklist item or a real pipe table (a pipe row followed by its `|---|` delimiter) counts as markdown; a bare bullet list of URLs is **still** a one-column delimited list, exactly as before. Verified: `- https://a` / `- https://b` as `.txt` and as `.md` both stay delimited.

- [x] **One `FORMAT_INFO` row plus one parser** — `EXT_FORMAT` aliases `.md`, `.markdown`, `.mdown`, `.mkd`, then a `parseMarkdownText(text)` returning the same 2D string matrix every other parser returns. Nothing downstream changes; that is what the format layer is for.
- [x] **Content sniffing has to do the work**, because markdown has no magic bytes. `sniffTextFormat` currently returns `null` for anything not starting with `[`/`{`/`<`, so this means adding a `looksLikeMarkdown` test (task-list lines, a pipe table with its `---` delimiter row, ATX headings) *without* stealing files from the delimited-text parser — a `.txt` of `- url` lines must keep behaving as a one-column list unless the markdown signals are unambiguous.
- [x] **Shapes to support, in priority order:**
  - [x] **GitHub-style task lists** — `- [ ]`, `- [x]`, `* [X]`, and numbered items. Nested items are **flattened** into their own rows, so no link is lost; no prefix is added, because the indent carries no meaning downstream once every row is a card.
  - [x] **Pipe tables** — `| Name | URL | Status |`, the `|---|` separator consumed (alignment colons tolerated) and `\|` escapes respected. A cell that is a *single* link resolves to its target, so a URL column holds a URL rather than a label.
  - [x] **Bullet / numbered lists of links** — bare URLs, `<https://…>` autolinks, `[label](https://…)` inline links, and bare `mailto:`/`tel:`/`sms:` targets (kept as their bare value so the app's own predicates and the MailLayer/PhoneLayer handoff still recognise them). A bullet with no link is **not** a task, which is what keeps a README's bulleted prose out of the queue; a *checkbox* item with no link is, because the checkbox is intent.
- [x] **Column mapping is the same four roles by value**, with no header heuristics needed: the checkbox gives Status for free (and `isCompleteValue` already accepts ticks), the first link on the line gives URL, and the text after it — split on an em dash or ` — ` / ` - ` separator — gives Notes. Lines with no link at all still become cards, because a task can be tracked without opening anything.
- [x] **Write-back: one-way import, like DOCX — and say why.** Settled as planned: `writable: false`, and the README says why in as many words. What makes it a *choice* rather than a limitation: completion and notes **could** round-trip losslessly (`- [x]` and trailing text are already in the file), but writing means reflowing prose, normalising bullets and choosing line endings — so if a "save the checkboxes back" path is ever wanted it has to be a line-level surgical edit (rewrite only the task lines, leave every other byte alone), with its own decision first. Presenting it as a checkbox in the meantime would be a lie.
- [x] **Fixture + the shared target:** both shapes shipped — `sample-links.md` (task list) and `sample-links-table.md` (pipe table) — each landing **10 cards / 7 visible / 3 complete** with the same four columns, checked in-browser through the real loader. One file per shape would be better than one file for both — a task-list fixture and a pipe-table fixture — since they exercise different code paths.
- [x] **Size/`sw.js` follow-ups:** both fixtures precached; `app.html` 164.1 → **173.7 KB**, standalone 1153.2 → **1162.8 KB**, bookmarklet `csv` 176.4 / `core` 186.0 / `full` 1122.6 KB, extension **1194.3 KB**.
- [x] **`sample-links.xml` now meets the shared target** (found while sweeping the fixtures in v0.12): it had been feed-shaped (`title`/`link`/`notes`) and landed **3 columns, 0 statuses, 10 visible** where every other fixture lands 4 columns / 3 complete / 7 visible — despite `history.md` claiming all four measured fixtures mirror the CSV. Fixed by giving each item a `<status>` element (4 columns, 3 complete, 7 visible, checked in all three suites), which is what makes the XML importer's element-to-column mapping testable at all.
