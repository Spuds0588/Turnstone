Bookmarklet Available

A bookmarklet is a bookmark whose URL is a program. Click it on any page and Turnstone opens there — as an overlay you can close again — instead of in a new tab or a new site. It asks for no install, makes no network requests, and loads no libraries: the parsers travel inside the bookmark itself. That is what makes it the edition to reach for on locked-down, air-gapped or strict-CSP machines.

Install it — drag to your bookmarks bar

1

Show your bookmarks bar if it is hidden: Ctrl+Shift+B (Windows/Linux) or ⌘+Shift+B (macOS).

2

Drag one of these links onto that bar. The variant you drag decides how much it can carry (table below).

3

Open any page — a spreadsheet listing, a docs site, anything — and click the new bookmark. The workspace appears over that page.

4

Drop a .csv / .xlsx list anywhere on the page, or press Demo list to see it work first. ✕ Close in the top bar puts the page back exactly as it was.

Test it in a minute

1

Click the bookmarklet on any page. The bar at the top shows the variant, plus Copy state, Restore state and ✕ Close.

2

Press Demo list — five cards, no file needed — then tick ✓ Complete on one and type a note.

3

Drop a real list anywhere on the page. A file with Status/Notes columns comes back with its progress intact (the same round-trip the app does).

4

Press Copy state, then ✕ Close, then click the bookmarklet again and Restore state — paste, and the queue returns with statuses and notes.

5

Export CSV from the ☰ menu to keep the work outside the page.

What the bookmarklet does and does not do

It does: cards, ✓ Complete / ↺ Incomplete, notes, sorting, column presets, search, the same open modes (tabs / browser tab / popup), the same exports, the same file-round-trip resume — the whole app, not a cut-down clone.

It does not:

  • Keep anything after the tab closes. A bookmarklet runs on someone else's origin, so storage is memory-only by design — the sidebar chip says “this tab only — export to keep”. Carry a queue with Copy state/Restore state, or export a file. The hosted app is the edition that remembers.
  • Write back into a picked file unless you chose the full variant (that needs SheetJS's writer). csv and core import workbooks one-way and export CSV.
  • Promise pixel-perfect styling on strict-CSP sites. The overlay needs no CSP exemption to run — scripts, styles and DOM are all constructed by the payload — but a site with a strict style-src drops the app's handful of inline style attributes, so a few dialogs look plainer. Everything still works.
  • Fetch a remote list on a site with a closed connect-src. Local drops are unaffected; pasting a URL there fails with a fetch/CORS message rather than silently.

The overlay is isolated: the host page's globals, storage and layout are left alone, and closing it removes everything it added. Nothing is uploaded and nothing is fetched.

Standalone single-file build Available Beta

turnstone-standalone.html is the whole app in one document — shell, PapaParse, SheetJS and the artwork inlined. Download it, double-click it, work. Nothing to install, nothing to serve, no network.

⤓ Download turnstone-standalone.html ▶ Open it instead

Built for USB sticks, internal shares, and air-gapped or locked-down machines. Regenerate it with node assets/build-standalone.js.

  • Everything works except what a file:// page cannot do: local files, every format, cards, link modes, exports and the file round-trip all behave exactly as in the hosted app.
  • No PWA install prompt (there is no sw.js beside a copied file — offline already works, because everything is local), and remote ?file= URLs are unreliable from file://: a browser rule, not a Turnstone one.
  • Planned: a CSV-only variant (no binary parser at all) for environments that cannot ship SheetJS. The app-side degradation logic is already in place — it is a build flag.

Hosted web app Available

The canonical edition, and the one to use if you want persistence and write-back: spuds0588.github.io/Turnstone/app.html.

  • All input formats: CSV, TSV, XLSX/XLS/XLSM/XLSB/ODS, JSON, HTML tables, XML feeds — PDF is detected and refused with a reason rather than mangled.
  • Silent write-back to CSV/TSV/XLSX in Chromium (File System Access API); elsewhere exports plus browser-storage snapshots.
  • Installable as a PWA, and works offline from the service-worker cache.
  • Remembers: recent files, statuses, notes, column presets, open mode, theme.

If what you need isn't supported, go here

You want to…Use
Open a .xlsx, .xls, .xlsb or .ods file The web app, the standalone build, or the bookmarklet's core/full variants. The bookmarklet's csv variant refuses workbooks and says so.
Save back into a spreadsheet from a bookmarklet The full bookmarklet variant (it carries SheetJS's writer), or the web app — which writes back silently in Chromium.
Keep a queue between sessions The web app (storage + write-back), or Copy state/Restore state in the bookmarklet, or Export CSV/XLSX from any edition.
Work completely offline, with no host and no network The standalone build.
Run it on a machine where nothing may be installed and nothing may be fetched The bookmarklet's csv (~142 KB, no libraries) or core (~152 KB) variant.
Use a format nothing supports yet (PDF tables, Markdown lists, Word docs) Export to CSV/XLSX first — every edition reads those. The roadmap is in todo.md.
Pin it to a desktop or taskbar like an app The web app as a PWA (Chromium, over HTTPS), or the standalone file plus a desktop shortcut.
