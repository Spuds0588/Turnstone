Which version?

Turnstone is one app with four front doors. They do the same job — turn a link list into a queue you work through — but they run in different places and carry different amounts of machinery. Pick by where you are allowed to run things, not by which one sounds cleverest.

Start with the web app Recommended

For almost everyone: open a page, drop your file, work. It is the full experience, it remembers your progress between visits, and in Chromium it saves straight back into your spreadsheet with no save button. If you can install a browser app, install it and skip the rest.

The other three exist for when that does not fit — a machine where nothing may be installed, a network with no route out, a browser that cannot write to your file, a site you are not allowed to leave. That is the entire reason the list below is longer than one.

Pick by what you are up against

Find your situation below; the second line is the edition that handles it. Where two are listed, the first is the easier one to live with.

Your situationUseWhy
A normal desktop or laptop, an ordinary browser, and you just want to get through the list Web app Most capability, least setup. Remembered state and silent write-back.
You want it to look and behave like an installed program, and work offline Web app, installed as a PWA Its own window, its own icon, offline from the cache after the first visit.
Nothing may be installed and nothing may be fetched — air-gapped, locked-down, or a shared machine Standalone build One HTML file, no server, no network, no admin rights. Full app inside it.
You cannot leave the page you are on, or the browser is stripped of extensions Bookmarklet (core) A bookmark, not an install. The app is composed as an overlay on the page you are already on.
The site blocks framing, and you want the queue visible next to it anyway Chrome extension No iframes at all: links open as real tabs and the panel drives them.
Firefox or Safari Web app, or the standalone build The extension needs Chromium's Side Panel API. Everything else is browser-agnostic.
You need it to survive closing the window and coming back tomorrow Web app or the extension Both keep statuses, notes and presets locally. The bookmarklet is memory-only by design.
An AI assistant found or generated your list Workspace link — any edition The rows travel inside the URL, so one link opens a ready queue with nothing to download — or your agent can produce a file instead, which every edition opens.
Your list is a real spreadsheet (.xlsx, .xls, .ods) Web app, the standalone build, or bookmarklet core/full Only the bookmarklet's csv variant cannot open a workbook — and it says so.
Your list is a Word table (.docx) Any of them — web app, standalone, or any bookmarklet variant Word files are unpacked with the browser's own ZIP reader, so DOCX needs no library and works even in the zero-library csv bookmarklet. Legacy .doc is refused with a reason.
Your queue lives in a README or a Markdown note (.md) Any of them Markdown is plain text, so it needs no library — GitHub-style task lists become cards with their checkboxes as statuses, and pipe tables work too. Read-only by choice: Turnstone never rewrites a document.
Your list is people — emails and phone numbers Web app, standalone build or the extension These three embed MailLayer and PhoneLayer, so an address opens a webmail composer and a number a provider picker. The bookmarklet deliberately leaves them out — its modals would land in the host page's DOM — so there an address opens your system mail app and a number your dialler. It says so on the welcome panel.
The file is enormous, or you only need the links Bookmarklet csv About 296 KB with no libraries at all. Nothing gets parsed that you did not need.

The four editions

Web app Start here

The full experience, hosted. Split-pane workspace, every input format, silent write-back to your file in Chromium, installable as a PWA, and it remembers your queue.

Needs: a normal browser. Nothing to install.

Agents, and what each edition can be handed Read this first

An agent can always produce the list — as a link, or as a data file — and every edition here can now open either one. Whether it can drive the thing that opened it is a separate question, and for the extension the answer is no.

EditionAn agent can hand it…What it cannot do
Web app A workspace link, or a spreadsheet to load. Both open the same queue. Nothing is in the way: a link is a URL, and you click it.
Standalone The same link, or the file — whatever reaches the offline machine. Reach that machine itself, or install anything. You copy the file across and open it.
Bookmarklet The list, as a link or a file. Click your bookmark. An agent cannot act inside your browser, and a bookmark lives in your bookmarks bar.
Chrome extension A data or spreadsheet file — CSV, TSV or XLSX — which you open in the side panel, or a workspace link you paste into the panel (or open from its ☰ → Open a workspace link… dialog). Drive the panel, and that is not going to change: it would take its own Chrome with this extension loaded and a panel open, which a coding agent in a sandbox, a headless browser or on another machine does not have. A link reaches this panel by paste, never by address bar — so this is the one edition where a link is a thing you carry across by hand.

This is a limit of browser side panels rather than of Turnstone, and it is worth knowing before wiring an agent into a workflow: ask it for a file or a link and every edition here opens it, the extension included — the difference is only how the link gets in (a click everywhere else, a paste in the panel). Either way the list arrives ready to work, and nothing is uploaded on the way.

Not for any of them Honest gaps

Some things none of the four will do, so that you do not go looking: there is no PDF table parser (export to CSV/XLSX first), no Google Drive or OneDrive sync, no crawling a page for links, and no server-side anything. Word documents (.docx) and Markdown (.md — task lists and pipe tables) are read, in every edition including the zero-library bookmarklet. Markdown is read and never written, and that one is a choice: a .md file is a document, not a data file. Where a gap is a plan rather than a decision, it is written down in todo.md.
