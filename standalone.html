Standalone build Available Beta

One HTML file holding the entire app — the workspace, both parsers, and the artwork, all inlined. Download it, double-click it, work. There is no server, no CDN and no checkout: since the app already makes zero external requests, this build is genuinely self-contained.

⤓ Download turnstone-standalone.html (1.25 MB) ▶ Open it instead

Who it is for

  • Machines where nothing may be installed and nothing may be fetched — but a file can be copied on. No admin rights, no browser extensions, no network.
  • USB sticks, internal shares, and internal wikis. One file to hand someone, and it keeps working after the network does not.
  • Air-gapped environments. Nothing is requested at boot, so an air gap changes nothing about how it behaves.
  • Anyone who wants a copy that cannot be broken by a deploy. The file you saved is the file that runs, forever.

What it does

  • Everything the web app does — local files, every input format, cards, statuses, notes, all the link modes, exports, ⚙ Columns (reorder, hide, rename, and a read-only / text / long text / dropdown / buttons editor per column), column presets, and the file round-trip resume.
  • Works from file://, straight off a double-click, with no local server.
  • Keeps its own state in the browser profile it runs in, so a queue survives closing the file and reopening it.

What it does not do

  • Offer to install itself as an app. There is no sw.js beside a copied file, so PWA registration is skipped — offline already works, because everything is local. The app logs this and moves on rather than failing.
  • Reliably load a remote ?file= URL. Browsers restrict cross-origin requests from file://. That is a browser rule, not a Turnstone one; a hosted copy or a local file works normally.
  • Write back silently on every browser. Write-back depends on the File System Access API being available on that browser — the same caveat as the web app — with export as the fallback.
  • Ship without the binary parsers yet. A CSV-only variant (no SheetJS at all, for environments that cannot carry a binary parser) is planned; the app-side degradation logic for it is already in place.

Get it

1

Download the file above — 1.25 MB, one document, nothing else needed.

2

Double-click it. It opens in your browser and works immediately.

3

Drop a CSV/XLSX/JSON/HTML/XML link list on it, or press Test CSV to confirm it is healthy.

Rebuilding it

The artifact is generated from app.html by node assets/build-standalone.js, which inlines both vendored libraries and the logo art and then asserts that no vendor/ or assets/ reference survived — so the build fails loudly rather than shipping a half-offline file. Its provenance (timestamp and source commit) is stamped into a comment at the top, and --check fails if the committed artifact is stale.
