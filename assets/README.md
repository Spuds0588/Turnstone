# assets/ — the brand assets and every generator

Nothing in this directory is loaded directly by `app.html` except the icons and the two theme
logos (via data URIs, so the app still opens from disk). Everything else here *produces* something
that is committed elsewhere: the standalone build, the fixtures, the crawl files, the social card,
the size registry. `app.html` is the only source file this project hand-writes for the app itself.

## The logo

The logo is a **circular grey stone with a dark-grey checkmark engraved into it** — the
engraving is faked with a second, offset copy of the check forming the groove's shadow lip.

| File | What it is |
|---|---|
| `logo.svg` | Master logo (theme-neutral). **Edit this one** when changing the design. |
| `logo-light.svg` | Light-theme variant — brighter stone so it holds contrast on white surfaces. |
| `logo-dark.svg` | Dark-theme variant — subtle rim so the stone reads on near-black surfaces. |
| `icon-192.png` / `icon-512.png` | Rasterized from `logo.svg` by `build-icons.js`; root-level copies are precached by the service worker. |
| `icon-maskable-512.png` | Maskable (safe-zone) variant for Android/adaptive icons. |
| `og-image.png` | The 1200×630 social card, generated by `build-og-image.js`. No text on it, deliberately: a wordmark would mean hand-authoring glyph outlines, and every platform renders `og:title`/`og:description` as real text beside the image. |

## The generators

Each one is zero-dependency, is safe to re-run, and takes `--check` where a stale artifact would be
a quiet lie. **Never hand-edit what these write** — regenerate and let the `--check` tell you.

| Script | Writes | Why it exists |
|---|---|---|
| `build-standalone.js` | `turnstone-standalone.html` | Inlines the app, PapaParse, SheetJS, both layers and the logo art into one document that works from `file://` with no network. |
| `make-fixtures.js` | every `sample-links.*`, `sample-portal-*`, `sample-invoice-*`, `sample-vendor-*`, `sample-compliance-*`, `sample-meeting-*`, `sample-queue-email.eml`, `sample-saved-queue.mht` | One definition of the canonical queue plus the workflow family, rendered into every container, so a fixture cannot drift from what the tests expect. `--check` fails if the tree differs; the xlsx, and both contact-list CSVs, had each quietly lost a note before this existed. |
| `build-site.js` | `sitemap.xml`, `robots.txt` | The page list comes from the directory, so adding a page is all it takes to be in the sitemap. It then checks the agent-facing graph as filesystem facts: canonicals, markdown twins, `llms.txt` links, `og:image`, JSON-LD parsing, **structured data against the page it is on**, the 1,000-word prose budget on `index.html`, and the top bar. |
| `build-icons.js` | `icon-192.png`, `icon-512.png`, `icon-maskable-512.png` | Hand-rolled SVG rasterizer + PNG encoder, exported behind a `require.main` guard so `build-og-image.js` reuses both instead of keeping a second copy. |
| `build-og-image.js` | `og-image.png` | The social card, built from the logo geometry and the brand background. |
| `lib/minizip.js` | *(library)* | The hand-written ZIP writer `make-fixtures.js` uses for the DOCX and XLSX fixtures, with a fixed member order so the bytes are reproducible. |
| `sizes.js` / `sizes.json` | `sizes.json` | The artifact size registry. The guide pages quote sizes, and a quoted size that has gone stale is a page lying to the person choosing an edition. Every build records what it just produced here; the site reads one small JSON instead of downloading 2.3 MB to measure. |

### The one chore a rebuild leaves behind

Rebuilding an artifact changes its byte size, and `site.js` rewrites the numbers on the guide pages
at runtime — which is exactly why the **`data-size-fallback` text** beside them is the copy that goes
stale unnoticed: it is what a reader with JavaScript switched off, and most crawlers, actually see.
`build-site.js` compares that text to `assets/sizes.json` using the same formatting `site.js` uses,
and fails with the two numbers side by side. So after any rebuild: rewrite the
`data-size-fallback` values (and the visible text) on `versions.html`, `standalone.html` and
`extension.html`, then run `node assets/build-site.js --check`.

## Rules

- **SVGs are the source of truth**; never hand-edit the PNGs — regenerate them.
- The icon generator samples the logo's geometry directly (circle + check polyline), so if the
  master SVG's shapes change, update the `STONE`/`CHECK` constants at the top of
  `build-icons.js` to match.
- Light/dark variants exist for the few contexts where CSS `currentColor` tricks can't help
  (favicon-style uses, `<img>` in theme-aware spots). The app's welcome header swaps
  `logo-dark.svg` / `logo-light.svg` via its `data-theme` attribute.
- The favicon + apple-touch-icon in `app.html` are embedded data URIs of `icon-192.png` so
  the icon survives opening the app straight from disk.
