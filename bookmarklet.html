Bookmarklet

A bookmarklet is a bookmark whose URL is a program. Click it on any page and Turnstone opens there — as an overlay you can close again — instead of in a new tab or a new site. It asks for no install, makes no network requests, and loads no libraries: the parsers travel inside the bookmark itself. That is what makes it the edition to reach for when nothing may be installed and nothing may be fetched.

Reaching for this because the web app didn't fit? Good — that is exactly what it is for. On a normal machine, prefer the web app: it remembers your queue and writes back to your file. The bookmarklet trades both away for portability and a zero-install footprint.

Install it — drag to your bookmarks bar

1

Show your bookmarks bar if it is hidden: Ctrl+Shift+B (Windows/Linux) or ⌘+Shift+B (macOS).

2

Drag one of these links onto that bar. The variant you drag decides how much it can carry (table below).

3

Open any page — a spreadsheet listing, a docs site, anything — and click the new bookmark. The workspace appears over that page.

4

Drop a .csv / .xlsx list anywhere on the page, or press Demo list to see it work first. ✕ Close in the top bar puts the page back exactly as it was.

Test it in a minute

1

Click the bookmarklet on any page. The bar at the top shows the variant, plus Copy state, Restore state and ✕ Close.

2

Press Demo list — five cards, no file needed — then tick ✓ Complete on one and type a note.

3

Drop a real list anywhere on the page. A file with Status/Notes columns comes back with its progress intact (the same round-trip the app does).

4

Press Copy state, then ✕ Close, then click the bookmarklet again and Restore state — paste, and the queue returns with statuses and notes.

5

Export CSV from the ☰ menu to keep the work outside the page.

What it does do

Cards, ✓ Complete / ↺ Incomplete, notes, sorting, column presets, search, the same open modes (tabs / browser tab / popup), the same exports, and the same file-round-trip resume — the whole app, not a cut-down clone. It also files itself away cleanly: the overlay is isolated, so the host page's globals, storage and layout are left alone, and closing it removes everything it added. Nothing is uploaded and nothing is fetched.

What it does not do The trade

  • Keep anything after the tab closes. A bookmarklet runs on someone else's origin, so storage is memory-only by design — the sidebar chip says “this tab only — export to keep”. Carry a queue with Copy state / Restore state, or export a file. The web app and the extension are the editions that remember.
  • Write back into a picked file unless you chose the full variant (that needs SheetJS's writer). csv and core import workbooks one-way and export CSV.
  • Promise pixel-perfect styling on strict-CSP sites. The overlay needs no CSP exemption to run — scripts, styles and DOM are all constructed by the payload — and the app no longer carries a single inline style attribute, so the dialogs render whole even where style-src 'self' is enforced. Only the small stone mark is lost when img-src data: is refused; the wordmark stays.
  • Fetch a remote list on a site with a closed connect-src. Local drops are unaffected; pasting a URL there fails with a fetch/CORS message rather than silently.
