Share a list as a link

A Turnstone workspace link carries the whole list inside the URL. Open it and the queue is already there — rows, columns, statuses, notes, and the portal address its rows are worked at. No file to send, nothing uploaded, no account on either end. It works because a list is just text, and a URL can hold text.

Why put the list in the fragment

The payload goes after the #, and that choice is doing real work. A fragment is never sent to a server — so the host of the page, and everything between you and it, sees a request for app.html and nothing else. Your client names, invoice numbers and notes stay in the browser. It also means the link is not subject to the request-line limits servers impose on query strings: nginx's default 8 KB header buffer answers anything longer with a 414, and a long list would be refused by the host before any of our code ran.

Query strings still work, for a tool that can only append one — ?data= is read exactly like #data=. It is just the second-best place to put a list of somebody's clients.

The format

Two encodings, and the plain one exists because a person can write it by hand:

ParameterWhat it carries
dataThe list as percent-encoded text. Readable, debuggable, and the one to use for a handful of rows.
zdataThe list deflated with raw deflate and base64url-encoded, no padding. Four to six times smaller, which is the difference between a link that survives a chat client and one that gets trimmed.
sumOptional integrity token: the byte length and an FNV-1a 32-bit hash of the list, both in base 36, joined with a dot. Present on every link we build; ignored when absent, verified when present.
formatForces the reader: csv, tsv, json, md, xml, html. Without it the format is sniffed from the text, which is right most of the time.
linkA portal address to compose each row's link from: https://portal.example.com/ticket/{Ticket}. {Column} is percent-encoded into the URL, {Column|raw} is spliced verbatim, {0} addresses a column by position.
nameWhat to call the workspace, so the sidebar says Q3 approvals rather than Shared workspace.
open1 to open the first task as soon as the link loads.

Building one in three lines, in any language

There is no service, no API and no key: it is deflate, base64url, and a checksum. The only detail that matters is that the deflate stream must be raw (no zlib or gzip wrapper). Four steps, and the code below is all of them:

  1. Get the list as text. A CSV or TSV export, a JSON array, a Markdown task list, or a plain list of links, one per line.
  2. Deflate it raw and base64url it. The stream must be raw deflate — no zlib or gzip wrapper — and base64url with no padding.
  3. Put it in the fragment with a checksum. app.html#zdata=<payload>&sum=<length>.<fnv1a>, with the length and hash in base 36.
  4. Add a portal address if the rows have no links of their own. &link=https://portal.example.com/ticket/{Ticket} composes each card's URL from the row.
// Node — no dependencies
const zlib = require('zlib');
const b = Buffer.from(list, 'utf8');
let h = 0x811c9dc5; for (const x of b) { h ^= x; h = Math.imul(h, 0x01000193) >>> 0; }
const sum = `${b.length.toString(36)}.${(h >>> 0).toString(36)}`;
const url = 'https://spuds0588.github.io/Turnstone/app.html'
  + '#zdata=' + zlib.deflateRawSync(b).toString('base64url') + '&sum=' + sum;
# Python — standard library only
import base64, zlib
raw = list_text.encode('utf-8')
co = zlib.compressobj(9, zlib.DEFLATED, -15)          # -15 = raw deflate
payload = base64.urlsafe_b64encode(co.compress(raw) + co.flush()).rstrip(b'=')
url = f"https://spuds0588.github.io/Turnstone/app.html#zdata={payload.decode()}"
// In a page, with the platform's own streams
const stream = new Blob([new TextEncoder().encode(list)])
  .stream().pipeThrough(new CompressionStream('deflate-raw'));
const bytes = new Uint8Array(await new Response(stream).arrayBuffer());
const b64 = btoa(String.fromCharCode(...bytes))
  .replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');

The list with no links in it

Half of the queues people actually work are rows of ticket numbers, invoice IDs or vendor names, all of them living inside one system. There is no per-row URL to put in a column, so the link supplies the address instead, and Turnstone composes each card's link from the row's own values: 

#data=…&link=https%3A%2F%2Fportal.example.com%2Fincident%2F%7BTicket%7D

Every card then opens the right page of that portal, and only an http(s) result is ever turned into a link — a template cannot produce a javascript: URL.

For an AI agent, in one paragraph

Read the list, deflate it raw, base64url it without padding, compute the checksum, and assemble app.html#zdata=…&sum=…. Add &link= if the rows are keys into a portal rather than links of their own, and &name= if you want the sidebar to say what the list is. Then hand over the URL: opening it loads the workspace with no further setup, and a truncated link refuses to open rather than loading half a queue. The same specification, written for a machine to read, is in llms.txt and the Markdown version of this page.

Questions this answers

Does this upload my list?
No. Everything after the # stays in the browser, which is why the payload lives there and not in the query string.
How big can a list be?
A typical queue compresses to a few hundred characters. A 4,000-row export still lands around a fiftieth of its original size. Past 100 KB Turnstone warns that chat clients may trim the link; past 2 MB of list it refuses, because a URL is not a file.
What if the link arrives damaged?
Every link we build carries a checksum, so a link that lost its tail is refused with a reason instead of quietly opening a shorter queue.
Do the notes and ticks come along?
Yes — a link built from a workspace you have been working in carries the statuses and notes you have entered, not just the original rows.
Does it work offline?
Yes, once the app itself is cached. Opening a workspace link needs no network beyond loading the page.
